# group_mm

## 1. 测试方法

- 在海光bw1000上进行测试。共三轮独立进程，每轮每版 20 次预热、50 个有效 GPU-event 样本。
- 单次 kernel 的 GPU-event 计时，不使用 graph；编译、分配、参考计算及重置不计时。
- 下表合并每版全部 150 个样本；时间单位为 μs，加速比为 TLE P50 / Gluon 优化版 P50。

## 2. 改变了哪些 op 的 layout

**算子顺序：按 group 调度矩阵块 → 分块 GEMM → 输出 BF16 转换 → C 写回。**

**只改变完整输出 tile 的 C 写回布局**

- Gluon 基线：`#ttg.blocked<{sizePerThread = [1, 1], threadsPerWarp = [64, 1], warpsPerCTA = [2, 4], order = [0, 1]}>`。
- Gluon 优化版：`#ttg.blocked<{sizePerThread = [1, 8], threadsPerWarp = [2, 32], warpsPerCTA = [8, 1], order = [1, 0]}>`。

GEMM 的 A/B 读取、shared memory 和 MFMA 布局都没改；尾 tile 的写回布局也没改。两版均 `num_warps=8 / num_stages=3 / waves_per_eu=1`。下表为各组 M 之和×N×K×groups，输入 BF16；分组为均匀/对齐、均匀/尾块、偏斜或含空组。
