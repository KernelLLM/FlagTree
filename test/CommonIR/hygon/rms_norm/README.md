# rms_norm

## 1. 测试方法

- 在海光bw1000上进行测试。共三轮独立进程，每轮每版 20 次预热、50 个有效 GPU-event 样本。
- 每个 GPU-event 窗口重放 128 次 kernel，event 时间除以 128。编译、分配、参考计算、graph capture 及重置不计时；结果为热/复用工作集时延。
- 下表合并每版全部 150 个样本；时间单位为 μs，加速比为 TLE P50 / Gluon 优化版 P50。

## 2. 改变了哪些 op 的 layout

**算子顺序：**

- **前向：RMSNorm → 乘 weight → 输出，同时保存 inverse RMS。** 大 N 分支分两遍处理 hidden tile，流程相同。
- **dx：上游梯度乘 weight → RMSNorm 反向计算 → dx 写回。**
- **dweight：逐元素计算 x×dy×inverse RMS → 沿 row 求和 → partial dweight 写回。**

**改变前向 RMSNorm 和反向 dx 的向量布局**：下表变动配置中的输入/weight 读取、逐元素计算、hidden 求和输入和结果向量写回共用它。hidden 求和的结果是 scalar，不附布局。

布局均为 `#ttg.blocked`；每格按 **sizePerThread；threadsPerWarp；warpsPerCTA；order** 列出完整参数。

| 配置 / 改动的 op | Gluon 基线 layout 参数 | Gluon 优化版 layout 参数 |
| --- | --- | --- |
| 前向 1×128 BF16 / 前向 128×128 BF16 / 前向 1024×128 BF16 / 前向 128×128 FP32 / dx 128×128 BF16 | `[1]；[64]；[4]；[0]` | `[1]；[64]；[1]；[0]` |
| 前向 1×512 BF16 / dx 64×512 FP32 | `[2]；[64]；[4]；[0]` | `[1]；[64]；[4]；[0]` |
| 前向 64×512 BF16 / 前向 512×512 BF16 | `[2]；[64]；[4]；[0]` | `[8]；[64]；[1]；[0]` |
| 前向 1×1024 BF16 / 前向 64×1024 BF16 | `[4]；[64]；[4]；[0]` | `[2]；[64]；[8]；[0]` |
| 前向 256×1024 BF16 / dx 256×1024 BF16 | `[4]；[64]；[4]；[0]` | `[8]；[64]；[1]；[0]` |
| 前向 1×2048 BF16 / 前向 1×4096 BF16 / dx 64×4096 BF16 | `[8]；[64]；[4]；[0]` | `[2]；[64]；[8]；[0]` |

**改变 dweight 的逐元素计算和 row 求和布局**：

布局均为 `#ttg.blocked`；每格按 **sizePerThread；threadsPerWarp；warpsPerCTA；order** 列出完整参数。

| 配置 / 改动的 op | Gluon 基线 layout 参数 | Gluon 优化版 layout 参数 |
| --- | --- | --- |
| BF16 dweight | `[1, 8]；[2, 32]；[4, 1]；[1, 0]` | `[1, 2]；[1, 64]；[4, 1]；[1, 0]` |
| FP32 dweight | `[1, 4]；[1, 64]；[4, 1]；[1, 0]` | `[1, 4]；[1, 64]；[2, 1]；[1, 0]` |

dweight 归约结果使用该二维 layout 的 dim=0 slice。基线将它转为一维 blocked（`sizePerThread=[1], threadsPerWarp=[64], warpsPerCTA=[4], order=[0]`）再写回；优化直接用自然 slice 写回。row-wise inverse RMS 读取使用二维 layout 的 dim=1 slice。

未列出的配置保持原布局。所有配置均 `num_stages=2 / waves_per_eu=1`；dweight 表只计 partial kernel，不含后续汇总。
