# rms_norm_w8a16_fp8

## 1. 测试方法

- 在海光bw1000上进行测试。共三轮独立进程，每轮每版 20 次预热、50 个有效 GPU-event 样本。
- 每个 GPU-event 窗口重放 128 次 kernel，event 时间除以 128。编译、分配、参考计算、graph capture 及重置不计时；结果为热/复用工作集时延。
- 下表合并每版全部 150 个样本；时间单位为 μs，加速比为 TLE P50 / Gluon 优化版 P50。

## 2. 改变了哪些 op 的 layout

**算子顺序：RMSNorm → FP8 weight 解量化及乘权 → 输出。**

改变的是 **RMSNorm 的数据/归约布局、解量化权重乘法及输出写回布局**。grouped 分支按 `[quant group,group 内元素]` 组织输入，RMSNorm 求和前展平为一维，因此下面分别列出输入布局和求和输入布局。

布局均为 `#ttg.blocked`；每格按 **sizePerThread；threadsPerWarp；warpsPerCTA；order** 列出完整参数。

| M×N / 改动的 op | Gluon 基线 layout 参数 | Gluon 优化版 layout 参数 |
| --- | --- | --- |
| 1×4096：输入与归一化/乘权 | `[16]；[64]；[4]；[0]` | `[8]；[64]；[8]；[0]` |
| 1×4096：输出写回 | `[8]；[64]；[4]；[0]` | `[8]；[64]；[8]；[0]` |
| 128×4096 / 1×16384：输入与归一化/乘权 | `[1, 16]；[8, 8]；[4, 1]；[1, 0]` | `[1, 8]；[4, 16]；[4, 1]；[1, 0]` |
| 128×4096 / 1×16384：RMSNorm 求和输入 | `[16]；[64]；[4]；[0]` | `[8]；[64]；[4]；[0]` |
| 512×4096：输入与归一化/乘权 | `[1, 8]；[4, 16]；[8, 1]；[1, 0]` | `[1, 16]；[8, 8]；[4, 1]；[1, 0]` |
| 512×4096：RMSNorm 求和输入 | `[8]；[64]；[8]；[0]` | `[16]；[64]；[4]；[0]` |
| 512×4096：输出写回 | `[1, 8]；[4, 16]；[8, 1]；[1, 0]` | `[1, 16]；[8, 8]；[4, 1]；[1, 0]` |
| 64×8192：输入与归一化/乘权 | `[1, 16]；[8, 8]；[4, 1]；[1, 0]` | `[1, 8]；[4, 16]；[8, 1]；[1, 0]` |
| 64×8192：RMSNorm 求和输入 | `[16]；[64]；[4]；[0]` | `[8]；[64]；[8]；[0]` |
| 64×8192：输出写回 | `[1, 8]；[4, 16]；[4, 1]；[1, 0]` | `[1, 8]；[4, 16]；[8, 1]；[1, 0]` |

grouped weight scale 读取使用输入二维 layout 的 dim=1 slice，并随输入 layout 一起改变；1×4096 的 scale 读取直接使用该行的输入一维 layout。inverse RMS 则是 scalar，不是这个 scale 向量。

1×32768 及表中未列出的边界保持原布局。均 `num_stages=2 / waves_per_eu=1`；下表输入/输出 BF16、weight FP8。
