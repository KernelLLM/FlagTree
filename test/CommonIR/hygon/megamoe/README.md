# megamoe

## 1. 测试方法

- 在海光bw1000上进行测试。共三轮独立进程，每轮每版 20 次预热、50 个有效 GPU-event 样本。
- 使用 HIP graph，每窗口计完整的 L1 → FP32 workspace → L2 计算；通信、分配及重置不计时。6 个性能形状，另有 3 个正确性控制不计时。
- 负 expert index 的正确性控制使用合法的前缀填充，不表示未填充输入的原始 API 安全。
- 下表合并每版全部 150 个样本；时间单位为 μs，加速比为 TLE P50 / Gluon 优化版 P50。

## 2. 改变了哪些 op 的 layout

**算子顺序：FP8/FP4 解量化 → Gate/Up 投影（L1） → SwiGLU → Down 投影（L2） → topk 加权求和 → 输出。**

**Gate/Up 投影和 Down 投影的乘法、归约布局**

- Gluon 基线：`#ttg.blocked<{sizePerThread = [1, 1], threadsPerWarp = [16, 4], warpsPerCTA = [1, 4], order = [0, 1]}>`。
- Gluon 优化版：`#ttg.blocked<{sizePerThread = [1, 1], threadsPerWarp = [32, 2], warpsPerCTA = [1, 4], order = [0, 1]}>`。

- Gluon 基线把乘积组织为 **[输出维,归约维]**，沿 axis=1 求和，结果为 dim=1 slice。
- Gluon 优化版组织为 **[归约维,输出维]**，沿 axis=0 求和，结果为 dim=0 slice。

两层投影都是显式乘法加归约，不是 MFMA dot；权重解码、输入/激活广播和投影累加随这个二维布局调整。L1 workspace 与最终输出的写回布局不变。两版均 `num_warps=4 / num_stages=2 / waves_per_eu=1`。

下表为 tokens×H×I×experts×topk，性能输入 FP8、权重 FP4、scale UE8M0；experts=256 的被测路由只覆盖 expert 0–145。
