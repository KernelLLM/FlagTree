# router_gemm

## 1. 测试方法

- 在海光bw1000上进行测试。共三轮独立进程，每轮每版 20 次预热、50 个有效 GPU-event 样本。
- 每个 GPU-event 窗口重放 128 次 kernel，event 时间除以 128。编译、分配、参考计算、graph capture 及重置不计时；结果为热/复用工作集时延。
- 下表合并每版全部 150 个样本；时间单位为 μs，加速比为 TLE P50 / Gluon 优化版 P50。

## 2. 改变了哪些 op 的 layout

**算子顺序：A×B GEMM → FP32 C 写回。**

改变的是 **GEMM 中 B 的读取和 shared staging 布局**，不是 GEMM accumulator 或输出布局。

布局均为 `#ttg.blocked`；每格按 **sizePerThread；threadsPerWarp；warpsPerCTA；order** 列出完整参数。

| 配置 / 改动的 op | Gluon 基线 layout 参数 | Gluon 优化版 layout 参数 |
| --- | --- | --- |
| M=1/8/16：B 读取 | `[1, 8]；[16, 4]；[2, 1]；[1, 0]` | `[8, 1]；[8, 8]；[1, 2]；[0, 1]` |
| M=32/64：B 读取 | `[1, 8]；[16, 4]；[4, 1]；[1, 0]` | `[8, 1]；[8, 8]；[1, 4]；[0, 1]` |
| M=128/256/512：B 读取 | `[1, 8]；[8, 8]；[4, 1]；[1, 0]` | `[8, 1]；[8, 8]；[1, 4]；[0, 1]` |
| M=1024：B 读取 | `[1, 8]；[8, 8]；[8, 1]；[1, 0]` | `[8, 1]；[8, 8]；[1, 8]；[0, 1]` |

**B 的 shared staging：**

- Gluon 基线：`#ttg.swizzled_shared<{vec = 1, perPhase = 1, maxPhase = 1, order = [1, 0]}>`。
- Gluon 优化版：`#ttg.swizzled_shared<{vec = 4, perPhase = 1, maxPhase = 16, order = [0, 1]}>`。

B 的二维轴是 `[K,N]`。A 读取、MFMA accumulator、dot operand packing 和 C 写回布局不变。基线 B 为连续转置副本，stride=(N,1)；优化 B 为转置视图，stride=(1,K)，所以不只是 layout 变化。下表为 M×N×K，输入 BF16。
