# hc_split_sinkhorn_forward

## 1. 测试方法

- 在海光bw1000上进行测试。共三轮独立进程，每轮每版 20 次预热、50 个有效 GPU-event 样本。
- 使用 HIP graph 重放；tokens≤2048 时每窗口 32 次，tokens≥16384 时每窗口 4 次。event 时间除以重复次数，仅计 kernel 计算。
- 下表合并每版全部 150 个样本；时间单位为 μs，加速比为 TLE P50 / Gluon 优化版 P50。

## 2. 改变了哪些 op 的 layout

**算子顺序：**

- **Pre/Post 分支：仿射变换 → Sigmoid → Pre/Post mix 写回。**
- **Comb 分支：仿射变换 → 行 Softmax → Sinkhorn 行/列归一化 → Comb mix 写回。**

改变的是 **HC=4 时这些 op 的 token 向量布局**。同一 token 上的仿射、Sigmoid、Softmax、Sinkhorn 计算及三个输出都沿用这个布局。

布局均为 `#ttg.blocked`；每格按 **sizePerThread；threadsPerWarp；warpsPerCTA；order** 列出完整参数。

| 配置 / 改动的 op | Gluon 基线 layout 参数 | Gluon 优化版 layout 参数 |
| --- | --- | --- |
| tokens=16384 | `[1]；[64]；[4]；[0]` | `[1]；[64]；[1]；[0]` |
| tokens=65536 | `[1]；[64]；[8]；[0]` | `[1]；[64]；[1]；[0]` |

tokens=128/2048 不变。HC=2 是 scalar-only 分支，也没改。`BLOCK_N=128/256` → `64`，`num_warps=4/8` → `1`；迭代次数不变，均 `num_stages=1`。下表为 tokens×HC，输入 FP32。
